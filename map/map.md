# 舰C交互式海图实现路径文档

> 文档版本: 2026-08-12  
> 适用场景: 可交互海图 + 舰队编成约束联动  
> 坐标系: 左上角为原点 (0, 0)，画布尺寸 1200×720

---

## 1. 坐标系定义

### 1.1 原点与方向

- **原点 (0, 0)**: 画布左上角
- **X 轴**: 向右递增，最大值 1200
- **Y 轴**: 向下递增，最大值 720
- **所有节点坐标**: 直接采用游戏原始像素坐标，无需转换

```
(0,0) ──────────────────────────────→ X (1200)
  │
  │    ● A (300, 200)
  │         ╲
  │          ╲
  │           ● B (500, 400)
  │
  ↓
Y (720)
```

### 1.2 为什么不需要转换

游戏 `map_info.json` 中的 `spot.x` 和 `spot.y` 本身就是相对于左上角的偏移量。CSS 和 SVG 的坐标系同样以左上角为原点，因此天然一致：

| 系统 | 原点 | 方向 |
|:---|:---|:---|
| 游戏画布 | 左上角 | 右下 |
| CSS `position: absolute` | 左上角 | 右下 |
| SVG `viewBox` | 左上角 | 右下 |
| HTML Canvas | 左上角 | 右下 |

## 4. 渲染架构（四层叠加）

### 4.1 层级结构

```
┌─────────────────────────────────────┐
│  第4层: SVG 交互层                   │  z-index: 3
│  - 节点圆圈 (可点击)                   │
│  - 节点文字标签                       │
│  - 路线虚线 (可点击热区)              │
│  - 当前位置高亮                       │
├─────────────────────────────────────┤
│  第3层: 路线精灵 (可选)               │  z-index: 2
│  - 游戏原生路线贴图 (PNG 裁剪)        │
│  - 若不用精灵图，此层合并到 SVG       │
├─────────────────────────────────────┤
│  第2层: 节点标记精灵 (可选)           │  z-index: 1
│  - 游戏原生节点覆盖层                 │
│  - 若不用，SVG 层直接画圆圈替代      │
├─────────────────────────────────────┤
│  第1层: 海图背景图                   │  z-index: 0
│  - PNG 背景，等比例缩放               │
└─────────────────────────────────────┘
```

### 4.2 缩放对齐机制（核心）

**原则**: 背景图和 SVG 必须共用同一套逻辑坐标系，各自独立等比例缩放。

**具体做法**:

1. **声明统一坐标系**: SVG 设置 `viewBox="0 0 1200 720"`
2. **背景图缩放**: 宽度填满容器，`height: auto` 保持 1200:720 比例
3. **SVG 叠加**: 绝对定位覆盖背景图，`width: 100%`, `height: 100%`
4. **节点坐标**: 直接填入原始像素值 (x, y)，浏览器自动映射

**映射公式**（浏览器内部完成，无需手动计算）:

```
显示位置 = 原始坐标 × (容器实际宽度 / 1200)
```

**关键约束**:
- 禁止裁剪 (`object-fit: cover` 禁用)
- 禁止拉伸变形
- 禁止固定高度导致比例失调

## 5. 交互逻辑

### 5.1 状态流转

```
┌──────────────┐     点击节点/路线      ┌──────────────┐
│   初始状态    │ ─────────────────────→ │  选中状态     │
│  (无选中)    │                        │ (显示约束)    │
└──────────────┘                        └──────────────┘
       ↑                                        │
       │         点击空白处或切换海域              │
       └─────────────────────────────────────────┘
```

### 5.2 节点点击

**触发**: 点击 SVG 中的节点圆圈
**行为**:
1. 高亮该节点（放大圆圈、改变填充色）
2. 左下约束面板显示该节点的属性：
   - 节点名称（A / B / BOSS / 起点）
   - 节点类型（战斗 / 资源 / 漩涡 / 起点）
   - 该节点的原始约束条件（如"索敌 ≥ 33"）
3. 若该节点是路线终点，显示从起点到该节点的完整路线

### 5.3 路线点击

**触发**: 点击 SVG 中连接两节点的线段
**行为**:
1. 高亮整条路线（加粗、变色）
2. 左下约束面板显示该路线的通行条件：
   - 必需舰种（如"驱逐舰 ≥ 2"）
   - 必需属性（如"索敌值 ≥ 33"）
   - 禁止条件（如"旗舰不可为航母"）
3. 右侧舰船选择面板实时更新：
   - 不满足条件的舰娘置灰禁用
   - 必需舰种标签高亮提示

### 5.4 舰队调整后的反向联动

**触发**: 用户在右侧添加/移除/更换舰娘
**行为**:
1. 实时计算当前舰队满足哪些路线条件
2. 海图上高亮所有可达路线（绿色）
3. 不可达路线变灰或降低透明度
4. 若当前已选中某条路线，检查舰队是否仍满足：
   - 满足 → 保持高亮
   - 不满足 → 闪烁警告，提示具体缺什么

## 6. 约束条件系统

### 6.1 约束类型

| 类型 | 示例 | 来源 |
|:---|:---|:---|
| 舰种约束 | 驱逐舰 ≥ 2 | 人工整理 / KCNav 统计 |
| 数量约束 | 舰队舰数 ≤ 6 | 游戏规则 |
| 属性约束 | 索敌值 ≥ 33 | 人工整理 / KCNav 统计 |
| 旗舰约束 | 旗舰不可为航母 | 人工整理 |
| 装备约束 | 舰队需携带ドラム缶 | 人工整理 |
| 速力约束 | 舰队需为高速 | 人工整理 |

### 6.2 约束数据结构

```json
{
  "route_id": "1-1_A_to_B",
  "from": "A",
  "to": "B",
  "constraints": [
    { "type": "ship_type", "target": "DD", "operator": ">=", "value": 2 },
    { "type": "stat", "target": "sokutei", "operator": ">=", "value": 33 },
    { "type": "flagship", "target": "not", "value": "CV" }
  ]
}
```

### 6.3 约束计算时机

- **事前**: 用户点击路线时，查询该路线的预置约束
- **事后**: 用户调整舰队后，遍历所有路线计算可达性
- **实时**: 舰娘选择面板中，根据当前已选路线过滤可选舰娘

## 7. 响应式适配

### 7.1 断点定义

| 断点 | 布局模式 | 海图占比 | 操作适配 |
|:---|:---|:---|:---|
| ≥ 1024px | 左右分栏 | 55% 宽 | 精确点击节点/路线 |
| 768-1023px | 左右分栏（窄） | 50% 宽 | 精确点击 |
| < 768px | 上下堆叠 | 40vh 高 | 节点点击后放大浮层 |

### 7.2 移动端降级

- **缩放**: 默认缩放到海图完整可见，支持双指缩放
- **点击**: 节点区域扩大热区（半径从 16px 扩大到 24px）
- **详情**: 点击节点后底部弹出浮层，而非左下面板
- **路线**: 路线线宽加粗（从 3px 到 5px），提高触摸命中率

## 10. 关键注意事项

### 10.1 坐标精度

- 豆包识别出的坐标可能存在 ±5~10 像素偏差
- 建议用画图工具打开海图，鼠标悬停核对关键节点（起点、BOSS点）
- 最终精度要求：肉眼对齐即可，无需像素级完美

### 10.2 路线绘制

- 若不用游戏原生精灵图，SVG `<line>` 画直线即可
- 若路线有弯曲（如 5-3 的弧线），改用 SVG `<path>` 贝塞尔曲线
- 路线颜色建议：可达 = 绿色，不可达 = 灰色，选中 = 蓝色高亮

### 10.3 节点标签

- 起点 = "出撃" 或 "Start"
- 普通节点 = 字母（A, B, C...）
- BOSS 节点 = 加粗红色，半径稍大
- 资源点 = 绿色，可带图标

## 附录 B: 坐标系对照表

| 系统 | 原点 | X方向 | Y方向 | 与游戏坐标转换 |
|:---|:---|:---|:---|:---|
| 游戏画布 | 左上 | 右 | 下 | 无需转换 |
| CSS 绝对定位 | 左上 | 右 | 下 | 无需转换 |
| SVG viewBox | 左上 | 右 | 下 | 无需转换 |
| HTML Canvas | 左上 | 右 | 下 | 无需转换 |
| 数学坐标系 | 左下 | 右 | 上 | Y需取反: y' = 720 - y |

**结论**: 采用左上角为原点的坐标系，与游戏、CSS、SVG 全部天然对齐，零转换成本。
